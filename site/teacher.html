Teacher tools

Everything on this page runs in your browser. Your private key, its passphrase and the decrypted work never leave this computer. Step-by-step instructions: Guide 10: Java Lab assessments.

1. Create the submission key pair (once)

Students' work is encrypted with the public key; only the private key, unlocked with your passphrase, opens it. The private key file is saved encrypted with the passphrase (standard PKCS#8, PBKDF2-SHA256 600 000 iterations, AES-256), so the file alone is useless to anyone who finds it.

Key id

  1. Download the private key and keep a copy in two safe places (it cannot be recreated; write the passphrase down separately).

  2. Private gradebook repository: Settings, Secrets and variables, Actions: secret LAB_PRIVATE_KEY = the whole file content, and secret LAB_KEY_PASSPHRASE = the passphrase.
  3. Publish the public key as lab/teacher-public-key.pem in the lab repository:

3. Mark a whole session in the browser

Fetches every submission of the session from GitHub, decrypts it, checks the time window exactly as the robot does, compiles and runs the last accepted submission of each student with the in-browser compiler, and gives you marks.csv and a ZIP with every student's code and typing log. Without hidden tests the public sample cases are used; choose your gradebook's tests folder to use the hidden ones. (The private gradebook repository does the same on the real JDK; use either or both.)
